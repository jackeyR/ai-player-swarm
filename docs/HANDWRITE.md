## 0. 怎么用这份清单

```
第一遍  遮住「代码对照」列，按「验收」列自己写/自己说
```

## 2. 必须背下来的数字与公式（11 项）

这些是面试里「一问就知道你有没有真跑过」的东西，**必须开口即出，不能查**。

| # | 内容 | 文档出处 |
|---|---|---|
| N1 | **Little's Law**：并发 = 到达率(局/秒) × 停留时间(秒)；例：2 局/秒 × 360s ≈ 720 个并发对局 | 清单 §6.1 |
| N2 | **利用率**：ρ = 到达率 × 服务时间；ρ→1 时排队时间 ∝ ρ/(1-ρ)：95% 约是 80% 的 5 倍、99% 约 25 倍 | 清单 §6.1 |
| N3 | **Bot 规模**：需要的 bot 数 = 目标并发对局 × 每局人数 ÷ 房间利用率 | 清单 §6.1 |
| N4 | **LLM 成本算式**：1 万 bot × 5% × 每分钟 1 次 × 800 token ≈ 40 万 token/分钟 ≈ 2400 万 token/小时；全量则是 4.8 亿/小时 | 方案 §2.5 |
| N5 | **六个必埋指标的名称与目标**：`match_wait_seconds` p99<8s、`room_alloc_seconds` p99<300ms、tick 超预算<0.1%、会话错误率<0.5%、重连成功率>99%、`room_leak_gauge`=0 | 方案 §2.8；本仓库 [docs/SLO.md](SLO.md) |
| N6 | **两条 p99 的差**：脚本 bot 4.1s → 参数化 bot 8.7s（不是变差，是把尖峰压出来了） | 方案 §5.3 |
| N7 | **消融表三个数**：固定脚本 KS p=0.001、参数化 p=0.31、+2% LLM pilot p=0.44 | 方案 §5.3 |
| N8 | **思考时间的分布参数**：对数正态中位 0.6–1.2s、σ 0.5–0.7、截断 [0.15s, 8s]；操作间隔双峰 0.1–0.3s / 3–10s | 方案 §2.4.2 |
| N9 | **会话时长**：对数正态，中位 25–35 分钟（长尾决定同时在线，不是平均值） | 方案 §2.4.2 |
| N10 | **系统调优四个数**：`ulimit -n 65535`、单目标 IP 临时端口约 2.8 万、`somaxconn`、`tcp_tw_reuse` | 清单 A9/§6.2 |
| N11 | **你实测的三个数**（必须是你自己 `results/` 里的）：峰值 bot、goodput、匹配 p99 | 你的 `results/<run>/result.json` |

> N11 是唯一必须「用自己的数据」的一项。文档给的所有数字都是参考量级，
> 面试官问「你自己跑出来多少」时，背文档等于自曝没跑过。

## 6. 面试九问：答题骨架（提取自方案 §5.5）

文档每问都给了一个「→」式的抓手，这里把它扩成一句话骨架。**答案要自己讲**。

| # | 问题 | 答题抓手（一句话） |
|---|---|---|
| Q1 | 为什么不用 JMeter / k6？ | 长连接 + tick 驱动 + 有状态房间，不是请求-响应模型 |
| Q2 | bot 会不会先成为瓶颈？ | 单独测 bot 端基线、限速、分机器，报「控制器开销占比」 |
| Q3 | 怎么证明 bot 像真人？ | 分布对齐 + KS/Wasserstein + 公开数据来源，给数字 |
| Q4 | LLM 到底起了多大作用？ | 离线造玩家 + 2% pilot 探索；主力不用，讲清成本与可复现取舍 |
| Q5 | 怎么找瓶颈？ | 分层压测（登录/匹配/分配/房间）+ 每层 SLO + trace + 火焰图 |
| Q6 | 1 万个 bot 怎么调度？ | 控制面 + runner 池 + 声明式负载计划 + 结果回收；端口/fd/多源 IP 是硬约束 |

## 7. 先写哪 5 个（优先级）

按「面试出现频率 × 覆盖知识点的广度」排序，不要从 W1 开始顺写：

写完这 5 个再回头补 W2/W4/W7/W8。

## 附：与本仓库的对应关系

本仓库已经把文档里能被生成的部分全部落地了。所以这份清单里的「手写」，
本质上不是「从零实现」，而是：

```
1. 能独立写出关键 10-20 行（W 类）
2. 能不看资料说出数字与取舍（N 类 / Q 类）
3. 能写出属于自己的叙事（T 类）
```

如果你在某一项上只能「看懂」而不能「写出来」，那一项就是下一周该补的。

> 清单最后那句原话：**「每条都能说出它在哪一行代码里」**。
> 现在代码都在你手上，这项检查随时可以做。
